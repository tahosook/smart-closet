# スマートクローゼット機能・画面・データ仕様書 (docs/SPECIFICATION.md)

本ドキュメントは、Smart Closet (`smart-closet`) の画面仕様、レスポンシブ設計、データモデル、および推薦・冷却ロジックを明文化した仕様書である。

---

## 1. システム概要 & アーキテクチャ原則

- **完全サーバーレス・APIキーレス（フロントエンド）:**
  - 外部LLM APIへの直接通信コードは実装しない（ユーザー自身がGoogle AI Pro / Geminiにプロンプトを貼り付けて再計算するHuman-in-the-loop方式）。
  - 気象データのみ、APIキー不要の Open-Meteo API をクライアントサイド（ブラウザ）から直接フェッチする。
- **ローカルファースト ＆ オプションGASクラウド同期（Cloudflare Pages 自動ブートストラップ）:**
  - **朝1秒の即決原則:** すべての操作（着用記録・奥様NG・推薦判定）は、まず `localStorage` と React Context 上で 0ms で完結。
  - **ゼロ入力ブートストラップ:** Cloudflare Access 背後の本番環境では、Pages Function (`/api/bootstrap-config`) から安全に GAS URL とシークレット合言葉が自動取得され、端末ごとの初期手入力が不要（合言葉や URL が消えた場合も自動復元）。詳細インフラ構成は [docs/OPERATIONS.md](./OPERATIONS.md) 参照。
  - **端末間シームレス同期:** Google Apps Script (`gas/Code.gs`) Web App を介して、Pixel 9a と Mac mini の間で着用履歴・奥様NGをバックグラウンド（非同期 Simple Request POST）で自動同期。オフライン時は保留フラグを保持し、次回接続時に自動再送。
  - **Google スプレッドシート連携:** `wear_history`、`wife_ng`、`analytics`（60日未着用アイテムの断捨離アラート、主力エース集計）をシート上に自動構築。写真フォルダ ID は `meta_config` シートが唯一の正本。
- **データの正本 (Single Source of Truth):**
  - マスターデータは `src/data/closet.json`（Git管理）。
  - 日常の状態変化（着用履歴、緊急の奥様NGペア登録、インポートされたカスタムデータ）は `localStorage` に保存され、起動時にマージして表示される。
  - `localStorage` に登録された奥様NGペアは、1クリックで `closet.json` スキーマにマージした完全版JSONとしてエクスポート（ダウンロードおよびクリップボードコピー）可能。

## 2. 画面・タブ仕様

### 共通レイアウト & レスポンシブ設計
- **モバイル (Google Pixel 9a):**
  - 片手親指操作を重視した1カラム構成。
  - 下部に固定された4タブナビゲーション（朝モード、服追加・AI、旅行、全マトリクス）。
  - タップターゲットは最低 44x44px を確保。
- **デスクトップ (Mac mini / ワイド画面):**
  - コンテナ幅を最大 `max-w-6xl` に拡張。
  - 朝モード（`TodayView`）は「左ペイン：天気・シーン・シャツ選択」「右ペイン：おすすめパンツ＆拡大表示」の2ペイン構成で一望可能。
  - 全マトリクス表（`MatrixView`）は全15パンツ列を横スクロールなしで快適に閲覧可能。

### Tab 1: 朝モード (`TodayView.tsx`)
毎朝1秒でその日のコーディネートを確定するための画面。

1. **気象連動ウィジェット (`WeatherWidget.tsx`):**
   - デフォルト位置：千葉県我孫子市 (`35.8644, 139.9708`)。現在地取得への切替・再取得も可能。
   - 当日の最高気温・最低気温・現在気温・天気を取得し、気温に応じた推奨袖丈（半袖・七分袖・長袖）を自動判定。手動切替も可能。
2. **シーン切替:**
   - 「🏢 オフィス出社」と「🏠 リモート＆外出」を1タップで切替。
3. **シャツ選択グリッド:**
   - 気温・袖丈に合致するシャツを上部に優先表示（1タップで選択）。
   - 気温外のシャツはアコーディオン内に折りたたまれ、必要に応じて展開・選択可能。
4. **【1秒即決】おすすめパンツカード:**
   - 選択されたシャツに対し、相性スコア順に第1候補・第2候補・第3候補を大判写真カードで提案。
   - 各カードには「相性理由」「ドレス度」「今日これ着る（決定ボタン）」「奥様NG登録ボタン」を配置。
   - 写真または虫眼鏡アイコンをタップすると、上下コーディネートを並べた拡大プレビューモーダルを表示。
5. **冷却期間バッジ (`⚠️ 昨日着用（冷却中）`):**
   - 昨日（または直近記録日）に着用したパンツは自動的に順位が末尾に下げられ、警告バッジを表示。
6. **その他の着用可能パンツ & NG一覧:**
   - 第4候補以降のパンツ、およびNG判定されたパンツ（理由・奥様NG解除ボタン付き）をアコーディオンで確認可能。
   - **出社モード時は、ドレス度 3.0 未満のスウェット・ジョガー系はすべてNGリスト側に分類され、候補から除外される。**

### Tab 2: 服の追加・AIおまかせ登録 (`AiSyncView.tsx`)
新しい服を購入した際、Gemini Pro に写真とデータを渡して決定論的にマージ・クラウド同期するための画面。ユーザーの事前手動入力を極限まで撤廃し、「写真選択 → プロンプトコピー ＆ Geminiへ写真添付 → JSON貼り付け適用」の3アクション（必須入力ゼロ）で完結する設計。

1. **Step 1: 写真の選択・専用下書き枠への自動保存 ＆ 自動復元（条件1遵守）:**
   - スマホで写真を選択または撮影すると、Canvas で長辺最大1200px・JPEG品質0.85に自動リサイズ・圧縮。
   - **専用下書き枠（1枠限定・リロード耐性）**: 本保存用の `STORE_IMAGES` / `STORE_META` とは物理的に完全分離された専用 DB `smart_closet_draft_db`（ストア `'draft'`、キー `'CURRENT_DRAFT'`）へ即座に自動保存。
   - **画面再読み込み耐性**: Gemini アプリへの切り替え往復等でブラウザタブが再マウントされても、マウント時に下書き枠から自動復元。
   - **安全な分離**: 写真同期の `pruneImages` の走査対象外であり、誤削除や件数安全弁への影響が一切発生しない。
   - 明示的な「✕ 写真を取り消す」ボタンにより、中断ゴミを残さず消去可能。
2. **Step 2: 1行補足メモ ＆ 全自動判定用プロンプト生成:**
   - 種別選択や名前入力は必須から外され、写真で判別しにくい特徴（ストレッチ有無、麻混、ウエストゴム等）のための**任意の1行補足メモ欄**のみを前面に配置（手動固定用アコーディオンも併設）。
   - ［📋 Gemini相談用プロンプトをコピー］を押すと、シャツ・パンツ両方の次連番ID候補（`getNextSequentialId` で算出した `S10` / `P16`）、写真からの視覚的特徴（種別・名前・季節袖丈・スコア）判定指示、現有全服サマリー、および登録済み奥様NG一覧を組み込んだ相談プロンプトを生成。
3. **Step 3: 単一アイテムJSON貼り付け ＆ インライン確認・微修正パネル（条件2遵守）:**
   - Gemini から返ってきた1着分のJSONコードを貼り付けると、下に「📋 取り込み内容の確認・微修正」パネルがリアルタイム表示される。
   - **種別切替と相性自動クリア（条件2）**: 確認パネル上で種別（シャツ ↔ パンツ）を切り替えた場合、ドメイン関数 `switchDraftItemCategory` により ID が新種別の次連番へ自動更新され、**3つの相性リスト（`officeRecommendIds`, `remoteRecommendIds`, `ngIds`）がすべて空配列 `[]` に自動クリア**（`ngReason` も `'なし'` に初期化）され、未設定注記バナーが表示される。
   - 名前、季節・袖丈チップ、ドレス度・快適度スコア、メモの微調整もインラインで可能。
   - ［💾 JSONを適用して自動マージ・保存］を単独の主ボタン（フル幅）として配置。
   - **一括確定**: マージ成功と同時に、下書き写真を確定したID（例: `P16`）で本保存ストアへ永続化し、専用下書き枠を消去、GAS 連携済みの場合は Google ドライブ正本フォルダへ `{確定ID}.jpg` として自動アップロード。
   - **バックアップ・復旧アコーディオン**: ［JSON保存］、［JSONコピー］、および明確な日本語文言付きの［初期データに戻す］は「📦 バックアップ・復旧（ファイル保存・初期データに戻す）」折りたたみ内に集約され、誤操作を防ぎながら必要なGit管理・復旧作業に対応。

### Tab 4: 全マトリクス一覧 (`MatrixView.tsx`)
全アイテムの組み合わせ相性を一望し、ワードローブの死角やボトルネックを発見する管理者・分析画面。アイテム数増加（500セル超）でも破綻しない3層構造を採用。

1. **第1層：インサイト＆穴の発見ダッシュボード（最上部）:**
   - `analyzeWardrobeStats` によるワードローブ健全性サマリー（総組合せ数、出社◎相性数、NG組合せ数、健全率%）を表示。
   - ボトルネックアイテムの動的警告カード:
     - 出社◎が少ないシャツ（1着以下）
     - 出社◎が少ないスラックス（ドレス度3.0以上かつ出社◎1着以下）
     - NG集中アイテム（NG率40%以上）
     - 孤立アイテム（相性ペア極少）
   - 各要注意アイテムのバッジ・カードをタップすると、第2層（ドリルダウン）のフォーカス対象に即座に遷移。
2. **第2層：アイテム別ドリルダウン表示（1着フォーカスビュー）:**
   - 選択された1着（シャツまたはパンツ）に対し、相手側全アイテムとの相性をソート一覧（出社◎ → リモート○ → 着用可△ → 奥様NG🚨 → 絶対NG×）でカード表示。
   - 各カードをタップすると上下拡大プレビューモーダルが開き、奥様NGの即時登録・解除が可能。
3. **第3層：全体マトリックス表（高密度表＋統一フィルター＋モバイル折りたたみ）:**
   - 統一5フィルター: `すべて` / `⚠️ 要注意アイテムのみ` / `🏢 出社対応のみ` / `🧥 長袖のみ` / `☀️ 七分袖・半袖のみ` で瞬時に絞り込み。
   - モバイル向け折りたたみアコーディオン（画面を占有せず、必要な時だけ展開）。
   - 全セルのタップ領域を最低 44×44px（`min-w-[44px] min-h-[44px]`）確保。
4. **ワードローブ偏り分析＆買い足しレコメンド:**
   - 出社エース（ドレス度3.5以上）パンツの充足度、S1の相性パートナー状況を解説。
   - 次の連番ID（`getNextSequentialId` による採番）を用いた黒テーパードスラックス等の買い足し提案。

### クラウド同期・スプレッドシート連携モーダル (`GasSyncModal.tsx`)
ヘッダーの雲アイコンから呼び出し可能。「覚えなくていい」UI設計原則に基づき、通常表示は3要素のみに絞り、詳細・設定・復旧を折りたたみに整理。

1. **通常表示（デフォルトで見える3要素）:**
   - ① **状態表示カード:** 内部用語を排除した日常の言葉で表示（「同期済み（最新です）」「未送信の変更があります」「クラウドと同期しています...」）と最終同期日時。
   - ② **統合「今すぐ同期」ボタン:** 1タップで「未送信があれば先に送信（`pushToGas`）→ 最新取得（`pullFromGas`）→ 写真の差分チェック＆取得（安全弁付き `handleSyncImages`）」を一気通貫で自動実行。ユーザーが Push と Pull の選択を意識する必要を撤廃。
   - ③ **写真の状態表示:** 普段はローカル判定（0ms）で確認できた事実のみ「端末にN着分の写真を保存済み」と表示し、Google ドライブ側に更新やローカル未取得がある時のみ「写真の更新があります」を表示。
2. **折りたたみセクション（詳細・復旧・設定）:**
   - **詳細・復旧（個別でやり直す場合）:** 手動再取得「📥 シートから取り直す」、手動送信「📤 端末の内容でシートを上書きする」、写真再走査「🖼️ 写真データだけ再チェックする」を格納。
   - **接続設定:** ［☁️ クラウドから設定を自動取得］、GAS WebアプリURL、合言葉入力、**画像フォルダID（表示専用：スプレッドシートの `meta_config` シートが唯一の正本であることを明記し、クライアントからの誤上書きを防止）**、自動同期チェックボックス、設定保存ボタン。未連携時のみ初期状態で自動展開。
   - **セットアップガイド・初期構築用ツール:** 3ステップ手順、［📋 GASコードをコピー］、［合言葉を再生成］ボタン。
3. **最下部：危険操作:**
   - ［⚠️ 写真キャッシュ全消去］: 誤操作を防ぐため最下部に配置（確認ダイアログ付きで端末の IndexedDB 写真キャッシュを初期化、Google ドライブ正本は保持）。

## 3. データモデル (TypeScript型定義)

データモデルの厳格な TypeScript 型定義は [`src/types/closet.ts`](../src/types/closet.ts) が唯一の正本（Single Source of Truth）である。主要な型と設計意図の概要は以下の通り：

| 型名 | 用途・設計意図 |
| :--- | :--- |
| **`ClosetItem`** | 服1着の定義（ID、カテゴリ、名称、画像パス、季節・袖丈、ドレス度/快適度スコア、出社/リモートおすすめID配列、NG相手ID配列、NG理由、メモ）。 |
| **`ClosetData`** | 服アイテムのコレクション配列（`items: ClosetItem[]`）およびカスタムインポート更新タイムスタンプ（`updatedAt`）。 |
| **`WearRecord`** | 日常の着用履歴（一意ID、日付 `YYYY-MM-DD`、シャツID、パンツID、シーン、タイムスタンプ）。 |
| **`WifeNgPair`** | 奥様NGペア記録（シャツID、パンツID、登録理由、登録日時）。アプリ内判定で最優先除外される。 |
| **`RecommendationResult`** | 朝モード計算結果（パンツアイテム実体、順位、前日着用フラグ、総合スコア、相性理由、出社/リモートフラグ）。 |
| **`GasSyncConfig` / `Payload` / `Response`** | Google Apps Script（GAS）との双方向同期通信ペイロード。LWW（Last-Write-Wins）および削除追跡（`SyncTombstones`）による端末間マージを実現。 |
| **`GetImageSyncPlan*` / `FetchImages*`** | Google ドライブ画像同期（Phase 1〜2）の差分プラン策定・分割取得インターフェース。 |
| **`UploadImageRequest` / `Response`** | 新規服追加時の端末下書き写真から Google ドライブへの直接自動アップロード用インターフェース。 |
| **`ItemCompatibilityStats` / `WardrobeAnalysisResult`** | 全マトリクス画面（Tab 4）におけるワードローブ健全性サマリーおよびボトルネック判定データ構造。 |
| **`BootstrapConfigResponse`** | Cloudflare Pages Functions (`/api/bootstrap-config`) からのゼロ入力設定配布インターフェース。 |

## 4. 推薦・冷却スコアリングロジック

`src/hooks/useClosetStore.tsx`（および `src/utils/closetDomain.ts`）における `getRecommendationsForShirt(shirtId, scene)` の算出ロジック：

1. **除外フィルター (NG判定):**
   - ① `wifeNgPairs`（奥様NG）に該当するペアはNGリストへ。
   - ② `shirt.ngIds` または `pants.ngIds` に含まれるペアはNGリストへ。
   - ③ **出社モード（`scene === 'office'`）かつ `pants.dressScore < 3.0`（スウェット・ジョガー系）は、オフィス不適合としてNGリストへ。**
2. **基本スコア算出:**
   - 出社モード: `score = (pants.dressScore * 1.5 + pants.comfortScore) * (isPrimaryRec ? 1.5 : isSecondaryRec ? 1.2 : 1.0)`
   - リモートモード: `score = (pants.comfortScore * 1.5 + pants.dressScore) * (isPrimaryRec ? 1.5 : isSecondaryRec ? 1.2 : 1.0)`
3. **冷却期間ソート:**
   - 直近着用日（昨日または履歴の最新日）に着用されたパンツは `isYesterdayWorn = true` となり、**未着用パンツの後に末尾ソート**される。
