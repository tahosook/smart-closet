# スマートクローゼット機能・画面・データ仕様書 (docs/SPECIFICATION.md)

本ドキュメントは、Smart Closet (`smart-closet`) の画面仕様、レスポンシブ設計、データモデル、および推薦・冷却ロジックを明文化した仕様書である。

> [!NOTE]
> **全体見直しの基準書（地図ドキュメント）について:**
> 機能の棚卸し、各機能の本拠地と線引き（存続／文脈ショートカット／統合／削除済）、設計原則4つ、リビルド2層化（クイック／フル）、および全画面の統一用語集については、**[docs/FEATURE_MAP.md](./FEATURE_MAP.md)** を参照のこと。本仕様書は現行実装の仕様を記述する。

## 1. システム概要 & アーキテクチャ原則

- **完全サーバーレス・APIキーレス（フロントエンド）:**
  - 外部LLM APIへの直接通信コードは実装しない（ユーザー自身がGoogle AI Pro / Geminiにプロンプトを貼り付けて再計算するHuman-in-the-loop方式）。
  - 気象データのみ、APIキー不要の Open-Meteo API をクライアントサイド（ブラウザ）から直接フェッチする。
- **ローカルファースト ＆ オプションGASクラウド同期（Cloudflare Pages 自動ブートストラップ）:**
  - **朝1秒の即決原則:** すべての操作（着用記録・奥様NG・推薦判定）は、まず `localStorage` と React Context 上で 0ms で完結。
  - **ゼロ入力ブートストラップ:** Cloudflare Access 背後の本番環境では、Pages Function (`/api/bootstrap-config`) から安全に GAS URL とシークレット合言葉が自動取得され、端末ごとの初期手入力が不要（合言葉や URL が消えた場合も自動復元）。詳細インフラ構成は [docs/OPERATIONS.md](./OPERATIONS.md) 参照。
  - **端末間シームレス同期:** Google Apps Script (`gas/Code.gs`) Web App を介して、Pixel 9a と Mac mini の間で着用履歴・奥様NGをバックグラウンド（非同期 Simple Request POST）で自動同期。オフライン時は保留フラグを保持し、次回接続時に自動再送。
  - **Google スプレッドシート連携:** `wear_history`、`wife_ng`、`analytics`（60日未着用アイテムの断捨離アラート、主力エース集計）をシート上に自動構築。写真フォルダ ID は `meta_config` シートが唯一の正本。
- **データの正本 (Single Source of Truth):**
  - マスターデータは `src/data/closet.json`（Git管理）。
  - 日常の状態変化（着用履歴、緊急の奥様NGペア登録、インポートされたカスタムデータ）は `localStorage` に保存され、起動時にマージして表示される。
  - `localStorage` に登録された奥様NGペアは、1クリックで `closet.json` スキーマにマージした完全版JSONとしてエクスポート（ダウンロードおよびクリップボードコピー）可能。

## 2. 画面・タブ仕様

### 共通レイアウト & レスポンシブ設計
- **モバイル (Google Pixel 9a):**
  - 片手親指操作を重視した1カラム構成。
  - 下部に固定された4タブナビゲーション（朝モード、追加・相談、相性、管理）。
  - タップターゲットは最低 44x44px を確保。
- **デスクトップ (Mac mini / ワイド画面):**
  - コンテナ幅を最大 `max-w-6xl` に拡張。
  - 朝モード（`TodayView`）は「左ペイン：天気・シーン・シャツ選択」「右ペイン：おすすめパンツ＆拡大表示」の2ペイン構成で一望可能。
  - 相性表（`MatrixView`）は全15パンツ列を横スクロールなしで快適に閲覧可能。

### Tab 1: 朝モード (`TodayView.tsx`)
毎朝1秒でその日のコーディネートを確定するための画面。

1. **気象連動ウィジェット (`WeatherWidget.tsx`):**
   - デフォルト位置：千葉県我孫子市 (`35.8644, 139.9708`)。現在地取得への切替・再取得も可能。
   - 当日の最高気温・最低気温・現在気温・天気を取得し、気温に応じた推奨袖丈（半袖・七分袖・長袖）を自動判定。手動切替も可能。
2. **シーン切替:**
   - 「🏢 オフィス出社」と「🏠 リモート＆外出」を1タップで切替。
3. **シャツ選択グリッド:**
   - 気温・袖丈に合致するシャツを上部に優先表示（1タップで選択）。
   - シャツ一覧上部に分類フィルターピル（共通部品 `FilterPillBar.tsx`：`すべて` / `👔 1枚もの` / `🧥 羽織り`）を配置し、多数のシャツから1枚もの・羽織りを瞬時に絞り込み可能。
   - 羽織りアイテムにはカード上に `🧥 羽織り` バッジを表示。
   - 気温外のシャツはアコーディオン内に折りたたまれ、必要に応じて展開・選択可能。
4. **【1秒即決】おすすめパンツカード ＆ 羽織り手動追加:**
   - 選択されたシャツに対し、相性スコア順に第1候補・第2候補・第3候補を大判写真カードで提案。
   - 各カードには「相性理由」「ドレス度」「今日これ着る（決定ボタン）」「奥様NG登録ボタン」、および確定済みの「色バッジ（例: 🎨 濃紺）」と「実寸目安（例: 📏 W 82 / 股下 72cm）」を配置。
   - **羽織り手動追加アコーディオン（`🧥 羽織りを1着追加する（任意・手動）`）**:
     - 選択されたベースコーディネート（トップス＋パンツ）に対し、手動で羽織りを1着だけ追加選択可能。
     - 3列グリッドで現役の羽織りシャツ一覧を展開し、1タップで選択・解除。
     - **おすすめ自動提案ロジック（`calculateRecommendationsForShirt`）および相性軸（オフィス/リモート/NG/奥様NG）は一切変更せず、羽織りは自動提案されない（手動追加選択のみ）。**
     - 今日の決定バナーに `＋ 🧥 {羽織り名}` を表示し、クイック解除ボタン（✕）からワンタップで羽織りのみ取り外し可能。
     - 「今日これ着る」決定時（または決定後の羽織り追加時）に、着用記録（`WearRecord.outerwearId`）へ永続保存。
   - 写真または虫眼鏡アイコンをタップすると、上下コーディネートを並べた拡大プレビューモーダルを表示（色・実寸目安の確認が可能）。さらにモーダル内のシャツ写真・パンツ写真をタップすると、共通全画面写真ビューア（`FullscreenPhotoViewer.tsx`）により、その1着だけを余白・枠を排した画面いっぱいの最大サイズ（3:4比率・object-contain維持）で全画面拡大表示可能。左右スワイプでペアのシャツ⇔パンツを瞬時に切り替えでき（PCの前後ボタン・矢印キーにも対応）、ヘッダー（位置バッジ・ID・名前）も連動。スワイプ操作とタップ判定は競合せず、タップまたは閉じるボタン（✕）で元の上下モーダルへ即座に復帰（朝モードでは下部属性バーを出さず写真最大化を維持）。
5. **冷却期間バッジ (`⚠️ 昨日着用（冷却中）`):**
   - 昨日（または直近記録日）に着用したパンツは自動的に順位が末尾に下げられ、警告バッジを表示。
6. **その他の着用可能パンツ & NG一覧:**
   - 第4候補以降のパンツ、およびNG判定されたパンツ（理由・NGバッジ・奥様NG解除ボタン付き）をアコーディオンで確認可能。
   - **NGの組み合わせであっても、写真タップで開く上下コーディネート詳細モーダル（理由・NGバッジ表示）の「この組み合わせを着る」ボタンから着用記録が可能（NGリスト行に直接の着用ボタンは置かず警告一覧としての性質を保ちつつ、着用能力は維持。着用してもNG登録自体は解除されず、推薦側にも混ざらない）。**
   - 当日着用中のパンツがNGリスト内にある場合は、アコーディオンが一度自動展開される（その後は手動で開閉可能、ヘッダーに「本日着用中あり」バッジ表示、行内に「✅ 本日着用中」バッジ表示）。
   - **出社モード時は、ドレス度 3.0 未満のスウェット・ジョガー系はすべてNGリスト側に分類され、候補から除外される。**
7. **空状態（利用可能なシャツ0着時）の案内表示:**
   - すべてのシャツが片付けられているか未登録の場合、「利用可能なシャツがありません」案内カードを表示し、「管理」タブの「ワードローブ整理」セクションから「出す」で復帰できる旨を案内。

### Tab 2: 追加・相談 (`AiSyncView.tsx`)
新しい服の購入時やコーディネート・買い足しの悩みを Gemini に相談し、決定論的にマージ・クラウド同期するための画面。服の登録フロー（Step 1〜3）と常設の「Gemini スタイリスト相談」セクションで構成される。

1. **Step 1: 登録モード選択・写真の選択・A4用紙基準化案内・専用下書き枠への自動保存 ＆ 自動復元:**
   - **登録モード切替（44pxピル）**: 「👕 1着ずつ登録（通常）」と「🧥 まとめ撮り一括登録（推奨2〜3着・最大3着）」を1タップで切替。
   - **クライアント圧縮・解像度制御**: スマホで写真を選択または撮影すると、Canvas で自動リサイズ・圧縮。まとめ撮りモードでは切り抜き精度と画質維持のため長辺最大2000px（通常モードは1200px）、JPEG品質0.85に正規化。
   - **A4白用紙（210×297mm）基準化ガイド**:
     - 通常時: 服の隣にA4用紙を置いて撮影することで、AIがA4用紙を参照して照明の色かぶりを考慮した正確な色判定、主要実寸（cm）推定、服本体のみの自動切り抜き（3:4配置）を行う旨を案内。
     - まとめ撮り時: 「💡 **服同士を重ねず、少し間を空けて並べ**、その隣に **A4の白い紙（210×297mm）を1枚** 置いて撮影してください（推奨2〜3着・最大3着）。AIがA4用紙を全着共通の基準として色判定・実寸推定・着ごとの自動切り抜きを行います。」と案内。
   - **専用下書き枠（1枠限定・リロード耐性）**: 本保存用の `STORE_IMAGES` / `STORE_META` とは物理的に完全分離された専用 DB `smart_closet_draft_db`（ストア `'draft'`、キー `'CURRENT_DRAFT'`）へ即座に自動保存。
   - **画面再読み込み耐性**: Gemini アプリへの切り替え往復等でブラウザタブが再マウントされても、マウント時に下書き枠から自動復元。
   - **安全な分離**: 写真同期の `pruneImages` の走査対象外であり、誤削除や件数安全弁への影響が一切発生しない。
   - 明示的な「✕ 写真を取り消す」ボタンにより、中断ゴミを残さず消去可能。
2. **Step 2: 1行補足メモ ＆ 基準化プロンプト生成:**
   - 種別選択や名前入力は必須から外され、写真で判別しにくい特徴のための**任意の1行補足メモ欄**のみを前面に配置（通常モード時は手動固定用アコーディオンも併設、まとめ撮りモード時は着別自動判定のため非表示）。
   - 手動固定アコーディオン（通常モード）では種別・名前・季節袖丈に加え、**羽織り分類指定（AIにおまかせ / 👔 1枚もの / 🧥 羽織り）**を選択可能。
   - ［📋 プロンプトをコピー］を押すと、モードに応じたプロンプトをクリップボードに生成：
     - 通常モード: 1着分の判定プロンプト（次連番ID、13色パレット、境界アンカー、A4寸法推定、外接矩形 `cropBox`、羽織り分類 `isOuterwear: true/false`、現有ワードローブ一覧（区分付き）、奥様NG一覧）。
     - まとめ撮りモード: 写真内の全着（1〜3着、最大3着）を検出し `{ "garments": [ ... ] }` を出力するプロンプト。着ごとの個別 `cropBox` 出力、1枚のA4用紙を共通物差しとした各着の寸法推定、13色パレット・境界アンカー、羽織り分類指示、奥様NG 7原則、および**案B（バッチ内の服同士の相性は付けず、現存する相手カテゴリの服との相性のみを指定）**を厳密指示。
3. **Step 3: JSON貼り付け ＆ インライン確認・微修正パネル（基準化・まとめ撮り対応）:**
   - Gemini から返ってきた1着分のJSONコード、またはまとめ撮りJSON（`{ "garments": [...] }`）を貼り付けると、下に確認・微修正パネルがリアルタイム表示される。
   - **単一確認パネル・まとめ撮り確認カード（シャツ）**:
     - `👔 1枚もの / 🧥 羽織り` 切替ボタンを配置し、AI判定結果を1タップでインライン微修正可能（パンツには付与不可）。
   - **「登録の手間削減が最優先」の非ブロッキング色検証（1着登録・まとめ撮り共通）**:
     - `color` が13色パレット外（例: `"ラベンダー"`）または欠落している場合でも、エラーで登録を止めずアンバー色の警告バッジ（`⚠️ 色：未確定（目安：〇〇）`）として扱い、`color = undefined`（未確定）のまま登録を通す。
     - パレット外の色名は情報として失われないよう、決定論的ヘルパー `appendUnconfirmedColorNote` により `notes` の末尾に `（色の目安：〇〇 ※13色パレット外のため未確定）` を自動追記。
     - 確認パネル上で13色パレットチップから任意に確定色をタップしてその場で変更することも可能。後から「フル見直し ＆ 重複統合」でまとめて確定色を付与することも可能。
     - なお、色以外の検証（ID接頭辞とカテゴリの一致、スコア範囲 1.0〜5.0、寸法範囲 10〜200cm、異カテゴリ既存ID上書き禁止等）およびマスターデータ検証（`validate-closet.mjs`）は従来どおり厳格にエラー拒否を維持。
   - **まとめ撮り確認パネル（`kind === 'batch_garments'`）**:
     - 貼り付けられた服配列（1〜3着）を検知し、全着デフォルトでチェックON（登録対象）＆自動切り抜きONの状態で着別カードを表示。
     - **決定論的連番採番（`assignSequentialIdsForBatch`）**: 対象カテゴリの現在データから決定論的に次連番ID（例: `S10`, `P16`）を自動採番してバッジ表示。
     - **検証OK着の1タップ一括適用**: すべての着が検証OK（色未確定警告を含む）の場合、追加の個別入力なしに最下部の［💾 選択したN着を一括マージ・保存］ボタン1タップで即座に一括登録。
     - **着別カード機能（全操作 44px）**:
       - `☑ この服を登録する`: 除外トグル（OFFにすると対象外となり後続の連番IDが即座に繰り上がる）。
       - 種別切替（シャツ ↔ パンツ）: ドメイン関数により相性リストを安全に初期化。
       - 羽織り分類切替（👔 1枚もの ↔ 🧥 羽織り）: シャツの場合に1タップ切替。
       - 13色パレットチップ: 未確定色の任意確定、確定色変更。
       - 実寸目安（cm）入力欄: 10〜200cm・0.5cm刻み。
       - 3:4切り抜きプレビュー ＆ 切替トグル: 下書き写真から個別 `cropBox` で切り抜いた 3:4 プレビュー（900×1200px）。
       - 名前、季節・袖丈チップ、ドレス度・快適度スライダー、メモ、相性サマリー。
   - **保存・直列画像処理 ＆ 部分適用リカバリ**:
     - 適用成功した各着について、`cropAndNormalizeGarmentImage` で 3:4 画像（900×1200px）を生成し、IndexedDB（`saveImageBlob`）へ保存。GAS設定がある場合は Google ドライブ正本フォルダへ直列（シリアル）アップロードし、進捗（`n/m着`）をインライン表示。
     - **全着成功時**: 専用下書き枠を消去（`clearDraftImage`）し、フォームをクリーンアップ。
     - **部分適用時（一部着が色以外のエラーで失敗した場合）**: 成功した着は確実にマージ・画像保存され、失敗した着のみが `remainingDrafts` として `jsonInput` と確認パネルに残存。下書き写真もIndexedDBに保持されるため、ユーザーはその場で内容を微修正して即座に再試行可能（二重登録を完全防止）。
     - **Google ドライブ画像アップロード失敗時の未完了リカバリ**: ドライブへの画像送信のみが失敗した場合、未完了リスト（`failedDriveUploads`）を `localStorage`（`smart_closet_failed_drive_uploads`）へ永続化し、Step 1 および Step 3 に再試行バナー（`☁️ 失敗した画像（N着）のみ再試行`）を表示。服データを二重登録することなく、IndexedDB 内の画像からドライブアップロードのみを安全に再試行可能。
4. **常設セクション: Gemini スタイリスト相談:**
   - **🛍️ ワードローブ買い足し相談**:
     - 現役の全アイテム情報（相性配列・着用回数を含む、シャツ内訳「1枚ものX着 / 羽織りY着」表記）、奥様NG情報（注意喚起）、片付けた服（別枠）を埋め込んだ対話用プロンプトをワンタップでコピー。
     - 任意の1行相談メモ（例: 出社用パンツを増やしたい等）を入力してプロンプトに反映可能。
     - ユーザーが Gemini にプロンプトを渡し、自然言語の対話形式で自由に買い足しを相談（アプリ側での集計計算や回答取り込みは行わず、購入後はこのタブのStep 1〜3から写真＋A4用紙で登録して完結）。
   - **🔄 ワードローブ全体見直しの案内表示**:
     - 相性・羽織りの再判定（⚡ クイック見直し）や写真を正本としたフル見直し・重複統合（📸 フル見直し）の本拠地は「管理」タブへ集約された旨を案内。

### Tab 3: 相性 (`MatrixView.tsx`)
全アイテムの組み合わせ相性を一望し、ワードローブの死角やボトルネックを発見する相性分析専用画面。アイテム数増加（500セル超）でも破綻しない階層構造を採用。

1. **第1層：インサイト＆穴の発見ダッシュボード（最上部）:**
   - `analyzeWardrobeStats` によるワードローブ健全性サマリー（総組合せ数、出社◎相性数、NG組合せ数、健全率%）を表示（※片付けた服は除外して計算）。
   - ボトルネックアイテムの動的警告カード:
     - 出社◎が少ないシャツ（1着以下）
     - 出社◎が少ないスラックス（ドレス度3.0以上かつ出社◎1着以下）
     - NG集中アイテム（NG率40%以上）
     - 孤立アイテム（相性ペア極少）
   - 各要注意アイテムのチップ・カードをタップすると、第2層（ドリルダウン）のフォーカス対象にスムーズスクロールして遷移。
2. **第2層：アイテム別ドリルダウン表示（1着フォーカスビュー）:**
   - 選択された1着（シャツまたはパンツ）に対し、相手側全アイテムとの相性をソート一覧（出社◎ → リモート○ → 着用可△ → 奥様NG🚨 → 絶対NG×）でカード表示。

### 全体見直しモーダル (`WardrobeRebuildModal.tsx`)
管理タブの「🔄 全体見直し」から呼び出し可能。「⚡ クイック見直し」と「📸 フル見直し」の2層構造を持ち、モーダル内でもタブ切替可能。

1. **⚡ クイック見直し（2ステップ構成）:**
   - **Step 1: プロンプト生成 ＆ JSON取り込み:** 写真を使わず、登録済みテキストデータ（名前・色・季節・スコア・メモ）とルールに基づく軽量プロンプトをワンタップコピー。Geminiからの回答JSONを貼り付けまたはファイル選択で取り込み。
   - **Step 2: 差分比較 ＆ 選択適用:** 差分項目は**相性（出社/NG/理由）**と**羽織り分類（`isOuterwear`）**のみに厳格制限。他の項目が回答JSONに含まれても一切変化しない。
2. **📸 フル見直し ＆ 重複統合（3ステップ構成）:**
   - **Step 1: 重複の検出・統合:** 写真ハッシュ（SHA-256 / dHash）による二重登録検出、残す服（survivor）の選択、着用履歴の日付不変ID置換、GASドライブ写真ゴミ箱移動連動。
   - **Step 2: 写真シート ＆ Gemini分析:** 1枚最大12着のコンタクトシート自動合成・ダウンロード、13色パレット・寸法目安・判定アンカー準拠のプロンプトコピー、回答JSONの取り込み（全着完全性チェック付き）。
   - **Step 3: 差分比較 ＆ 選択適用:** 色（13色）、実寸、名前、スコア、メモ、相性、羽織りの全項目を差分表示。確定色および実寸は保護ロック（初期チェックOFF）により安全に保護。
3. **聖域データの不変保護（全モード共通）:**
   - 奥様NG（`wifeNgPairs`）、着用履歴（`wearHistory`）、片付け状態（`archived`）はどちらの見直しでも一切変更・上書きされない。

## 4. 推薦・冷却スコアリングロジック

`src/hooks/useClosetStore.tsx`（および `src/utils/closetDomain.ts`）における `getRecommendationsForShirt(shirtId, scene)` の算出ロジック：

0. **現役判定（片付け除外）:**
   - `archived: true`（片付けた服）のシャツまたはパンツは、推薦候補および相性評価から事前に完全除外される。
1. **除外フィルター (NG判定):**
   - ① `wifeNgPairs`（奥様NG）に該当するペアはNGリストへ。
   - ② `shirt.ngIds` または `pants.ngIds` に含まれるペアはNGリストへ。
   - ③ **出社モード（`scene === 'office'`）かつ `pants.dressScore < 3.0`（スウェット・ジョガー系）は、オフィス不適合としてNGリストへ。**
2. **基本スコア算出:**
   - 出社モード: `score = (pants.dressScore * 1.5 + pants.comfortScore) * (isPrimaryRec ? 1.5 : isSecondaryRec ? 1.2 : 1.0)`
   - リモートモード: `score = (pants.comfortScore * 1.5 + pants.dressScore) * (isPrimaryRec ? 1.5 : isSecondaryRec ? 1.2 : 1.0)`
3. **冷却期間ソート:**
   - 直近着用日（昨日または履歴の最新日）に着用されたパンツは `isYesterdayWorn = true` となり、**未着用パンツの後に末尾ソート**される。

## 5. Google Apps Script バックエンド仕様 (`gas/Code.gs`)

### スプレッドシート構成と10列化
1. **`wear_history` シート:**
   - ヘッダー（10列）: `ID`, `日付`, `シーン`, `シャツID`, `シャツ名`, `パンツID`, `パンツ名`, `タイムスタンプ`, `羽織りID`, `羽織り名`
   - **後方互換性保証**:
     - 既存の8列シート（`羽織りID`, `羽織り名` 列が存在しない状態）から読み取る場合、`readWearHistory` は動的に列数を判定し、列9・10を `undefined` として安全に読み取りクラッシュしない。
     - 書き込み時は自動的に10列ヘッダーを保証し、`outerwearId` および対応する服名称を保存。
2. **`analytics` シートの集計:**
   - 着用履歴から各アイテムの着用回数を集計する際、`shirtId`, `pantsId` に加え、`outerwearId` も1回の着用実績としてカウント（同一記録内で重複しないよう `Set` で一意化）。
3. **Fail-Closed 認証とロック制御:**
   - `meta_config` シートに登録されたシークレットトークンによる Fail-Closed 認証（未登録・不一致は即座に拒否）。
   - `LockService` による最大10秒のスクリプト排他制御により、複数端末からの同時 Push によるデータ競合・上書き消失を防止。
