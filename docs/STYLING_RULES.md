# コーディネート判定ルール＆ワードローブ分析 (docs/STYLING_RULES.md)

新しい服を追加し、Gemini（Google AI Pro）で相性マトリクス（`src/data/closet.json`）を再計算する際は、以下のルールを絶対基準とする。

---

## 1. 鉄壁の配色・組み合わせ3原則（奥様ダメ出し回避ルール）

### ① 同系色・近似トーンの上下衝突（セットアップ崩れ）の禁止
- **濃紺×濃紺の地雷:**
  - `S1`（濃インディゴシャツ）に濃紺・インディゴ系パンツ（`P1, P5, P6, P8, P11`）を合わせると、作業着やパジャマ、スーツの上下間違いに見えるため**絶対NG**（`ngIds` に追加し、`ngReason` に「上下同系色の濃紺になり作業着・パジャマ見えするため」と記載）。
- **淡青×青デニムの地雷:**
  - `S3`（サックスシャンブレー）に薄い青やブルーデニム（`P4, P7, P15`）を合わせると、全身が薄い水色で繋がり休日のおじさん感が出るため**絶対NG**。
- **淡色×淡色の膨張地雷:**
  - `S8`（生成り/クリームワークシャツ）に淡いグレージュや薄グレー（`P3, P9, P13`）を合わせると、上下の境界がぼやけて膨張して見えるため**絶対NG**。

### ② 柄×柄の完全禁止
- **柄物同士の衝突:**
  - 柄・ストライプシャツ（`S5` 小紋柄、`S6` 細ストライプ、`S9` ロンドンストライプ）と、柄・ストライプパンツ（`P5` パッチワーク、`P10` ヒッコリー、`P11` ピンストライプ）の組み合わせは**絶対NG**。
- **柄パンツの消化ルール:**
  - クセの強い柄パンツ（`P5, P10, P11`）は、必ず**白無地シャツ（`S2, S4, S7`）**の日に合わせて清潔感を担保する。

### ③ TPO（ドレス度×快適さ）の分離
- **オフィス出社 (`scene === 'office'`):**
  - パンツのドレス度 `3.5` 以上（`P8` 濃紺テーパード、`P9` グレーイージー、`P3` グレージュ、`P12` オリーブ、`P1, P6` 濃紺系）を優先推薦する。
  - **スウェット・ジョガー系（`P2, P4, P13, P14, P15`：ドレス度 `3.0` 未満）は出社候補から除外**する。
- **リモート＆外出・長距離移動 (`scene === 'remote'`):**
  - 快適さ（コンフォート度） `4.0` 以上を優先する。

## 2. 現在のワードローブ構造と買い足し指針（初期24着時点）

### 現状の偏り
- **シャツ9枚:** 「白系（6枚：`S2, S4, S5, S6, S7, S9`）」と「青系（3枚：`S1, S3` 他）」に大きく二分されている。
- **パンツ15本:** 出社エース級の綺麗めパンツが `P3`（グレージュ）、`P8`（濃紺）、`P9`（ミディアムグレー）、`P12`（オリーブ）の4本に集中している。
- **S1（濃インディゴ）の出社相手不足:** ネイビー系パンツがすべてNGになるため、合わせられる出社スラックスが `P3, P9, P12` の3本しかない。

### 最優先の買い足しターゲット
1. **黒（ブラック）の綺麗めテーパードスラックス（センタープレス・ストレッチ、通年）：【P16候補】**
   - 導入効果: `S1`（濃紺）、`S3`（サックス）、`S5`（小紋柄）、`S8`（生成り）すべての出社第1〜第2候補ハブとして組み込むこと。現在手持ちの黒パンツは `P2`（スウェット）のみで出社不可のため、最優先。
2. **チャコールグレーまたはモカブラウンのトップス（長袖シャツ/ニットポロ）：【S10候補】**
   - 導入効果: `P3`（グレージュ）や `P9`（グレー）、デニム系との大人っぽい秋・冬オフィスコーデの幅を拡大する。

## 3. 双方向整合性ルール（JSONマスターデータ更新時の必須規約）

`src/data/closet.json` を更新、または Gemini プロンプトで再計算させる際は以下のデータ整合性を厳格に保持すること：

1. **双方向の参照整合性:**
   - シャツ `S_x` の `officeRecommendIds` に `P_y` を含めた場合、パンツ `P_y` の `officeRecommendIds` にも `S_x` を含める（または secondary 推薦として機能させる）。
   - シャツ `S_x` の `ngIds` に `P_y` が含まれる場合、パンツ `P_y` の `ngIds` にも必ず `S_x` を含める。
2. **推薦リストとNGリストの排他性:**
   - 同一のIDが `officeRecommendIds` / `remoteRecommendIds` と `ngIds` の双方に同時に存在してはならない。
3. **ブラウザで登録された「奥様NG」の優先:**
   - ユーザーがブラウザ上で `🚨 奥様NG` に登録した組み合わせは、`closet.json` の静的設定よりも優先され、次回JSONエクスポート時に `ngIds` へマージされる。
